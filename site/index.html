AgentKit, layer by layer

AgentKit installs workflows into your coding agent (Claude Code, Codex, Cursor…). It adds skills (named workflows like /ak:plan, /ak:cook), specialist agents, event-driven hooks, and rules that shape behavior. This guide shows where each piece lives, when it runs, and which skill and flags to use for which job.

AgentKit, giải thích từng layer

AgentKit là bộ workflow cài vào coding agent (Claude Code, Codex, Cursor…). Nó thêm các skill (quy trình có tên như /ak:plan, /ak:cook), các agent chuyên trách, hook chạy theo sự kiện, và rule định hướng hành vi. Trang này giải thích mỗi phần nằm ở đâu, chạy khi nào, xử lý ra sao, và khi nào nên dùng skill nào với tham số gì.

The 30-second picture

Think of the model as a skilled chef. AgentKit hands it a recipe book (skills), a kitchen crew (agents), and house rules (rules). Door alarms (hooks) fire on events: session start, prompt sent, file edited. The ak CLI is the delivery service: it fetches signed kits, puts them in the right place for each kitchen (adapter), and updates or removes them.

Quick start

  1. Install the CLI. macOS/Linux: curl -fsSL https://agentkit.best/install.sh | sh. Windows PowerShell: irm https://agentkit.best/install.ps1 | iex. Add AK_CHANNEL=beta for beta. The binary lands in ~/.local/bin; open a new terminal.
  2. Verify. ak --version, then ak doctor --json.
  3. First-run setup. ak setup detects your runtimes, picks adapters, writes ~/.agentkit/config.yaml. It does not log in or install a kit.
  4. Log in. Preferred: ak login --api-key ak_live_... --no-interactive. Or email + OTP: ak login --email you@example.com. Check with ak whoami and ak licenses.
  5. Install the kit. ak kit init engineer --yes. Project scope by default; add --global for all projects.
  6. Restart your coding agent (or open a new session), then try /ak:help, /ak:agentkit "...", or /ak:plan "...".

Shortcut: ak onboard --kit engineer --target claude-code runs only the missing steps. --yes accepts prompts but never overwrites or takes ownership of files.

Architecture & layers

AgentKit has two halves. The install half belongs to the ak CLI: auth, download, signature check, install, update, remove. The execution half belongs to the runtime (Claude Code…): model, tools, permissions, lifecycle events. The CLI never "runs" a skill. It puts files where the runtime finds them.

Seven steps from release to result

1. Authenticated registryTrusted source of verified kits. Needs ak login and a license.
2. ak CLIAuth, version resolution, verify, install, update, diagnose, remove. Touches only files it knows AgentKit owns. Snapshots before writing.
3. Runtime adapterMaps kit content to each runtime's layout (Claude Code: ~/.claude/skills, agents, hooks, rules). Unsupported parts are kept as docs, dropped with a warning, or marked unsupported. Compatibility, not parity.
4. Coding agent (runtime)Discovers installed skills, agents, hooks, rules. Hooks are registered in hooks/hooks.json and fire on events.
5. Skill / agent workflowYou call a skill, or describe the outcome and the runtime picks one. Skills may delegate to subagents.
6. Project artifactsCode, plans/…/plan.md, phase-*.md, plans/reports/*.md, tests, docs, journals.
7. You reviewYou decide what to keep, commit, publish, or send. "AgentKit does not replace you."

Five building blocks

KIT

Kit

Versioned package of skills, agents, hooks, rules, and support files. Installing it runs nothing. The Engineer Kit = shared core + engineering skills (102 total).

SKL

Skill

A reusable workflow for one outcome. Its frontmatter holds argument-hint (syntax), when_to_use, and workflow.follows/precedes.

AGT

Agent

A specialist role for delegation. Not more authoritative than a skill. Start with a skill and let it delegate.

HK

Hook

Automation tied to a lifecycle event. Not a security boundary. A hook file alone doesn't prove it runs; adapters may narrow or drop hooks.

ART

Supporting artifacts

Rules, references, scripts, config, templates. They support workflows, never act alone.

name: ak:cook
description: "Implement features, plans, and fixes with structured workflow…"
user-invocable: true
when_to_use: "Invoke to implement known scope after requirements are clear."
argument-hint: "[task|plan-path] [--interactive|--fast|--parallel|--auto|--no-test] [--tdd] [--advice] [--yagni] [--skip-journal]"

The model sees every skill's description and uses it to choose when you don't name one. Phrasing your request like the when_to_use text helps it pick right.

Kiến trúc & các layer

AgentKit tách thành hai nửa. Nửa cài đặt do CLI ak sở hữu: xác thực, tải, kiểm chữ ký, cài, cập nhật, gỡ. Nửa thực thi do runtime (Claude Code…) sở hữu: model, tool, quyền, sự kiện lifecycle. CLI không "chạy" skill. Nó chỉ đặt file đúng chỗ để runtime tự tìm thấy.

7 bước từ release tới kết quả

1. Registry có xác thựcNguồn tin cậy phát hành Kit đã xác minh (site này chỉ nói về Engineer Kit). Cần ak login và license.
2. CLI akXác thực, resolve phiên bản, verify, cài, update, chẩn đoán, gỡ. Chỉ đụng tới file nó nhận ra là của AgentKit (ownership tracking). Chụp snapshot trước khi ghi.
3. Runtime adapterDịch nội dung kit sang cấu trúc mà từng runtime hiểu. Ví dụ với Claude Code là ~/.claude/skills, agents, hooks, rules. Thứ gì runtime không có tương đương thì bị giữ làm tài liệu, bỏ kèm cảnh báo, hoặc đánh dấu unsupported. Adapter là ranh giới tương thích, không phải lời hứa ngang bằng tính năng.
4. Coding agent (runtime)Tự khám phá skills, agents, hooks, rules đã cài. Hook được đăng ký trong hooks/hooks.json và chạy theo sự kiện.
5. Workflow skill / agentBạn gọi skill trực tiếp, hoặc mô tả kết quả mong muốn để runtime tự chọn. Skill có thể giao việc cho subagent.
6. Artifacts trong projectCode, plans/…/plan.md, phase-*.md, plans/reports/*.md, test, docs, journal.
7. Bạn reviewBạn quyết định giữ, commit, publish hay gửi. "AgentKit không thay thế bạn."

5 khối xây dựng

KIT

Kit

Gói có phiên bản, gom skills, agents, hooks, rules và file hỗ trợ. Cài kit không làm chạy mọi thứ bên trong. Engineer Kit gồm phần core dùng chung cộng các skill kỹ thuật, tổng cộng 102 skill.

SKL

Skill

Workflow tái sử dụng hướng tới một kết quả. Thường được gọi có chủ đích kèm mục tiêu hoặc đầu vào. Frontmatter chứa argument-hint (cú pháp), when_to_use, workflow.follows/precedes.

AGT

Agent

Vai chuyên trách để giao việc. Nó không có thẩm quyền cao hơn skill. Thường bạn không gọi agent trực tiếp, hãy bắt đầu bằng skill và để skill tự giao việc.

HK

Hook

Tự động hóa gắn với sự kiện lifecycle. Hook không phải ranh giới bảo mật, và có file hook chưa chắc nó đã được đăng ký hay chạy. Adapter có thể dịch, thu hẹp hoặc bỏ hook.

ART

Supporting artifacts

Rules, references, scripts, config, templates. Chúng phục vụ workflow chứ không tự hành động.

Life of a prompt

You open Claude Code and type /ak:cook "add CSV export to reports". Here is what AgentKit does at each beat. Hook names are real files in ~/.claude/hooks/.

SessionStart
session-init.cjs loads config, detects the project (type, package manager, framework, git root, worktree), sets env vars, and prints context: project name, plan naming {date}-{issue}-{slug}, plans/reports/docs paths. Runs again after /clear or compaction and points to the active plan.
Rules
Files in rules/ are already in the system context: primary-workflow (brainstorm → inspect → plan → verify → review), development-rules (KISS/DRY, no fake mocks, YAGNI only with --yagni), orchestration-protocol (how to brief subagents)…
UserPromptSubmit
dev-rules-reminder.cjs injects Session / Rules / Paths / Plan Context / Naming: date, timezone, report path pattern plans/reports/{type}-YYMMDD-HHmm-{slug}.md, active plan. secret-output-guardrail.cjs adds a reminder when the prompt touches secrets. simplify-gate.cjs hard-blocks ship/merge/pr/deploy when the diff is large (>400 LOC, >8 files, or one file +200 LOC) until code-simplifier runs; commit/release only warns. usage-quota-cache-refresh refreshes statusline quota.
Skill fires
The runtime loads ak-cook/SKILL.md. The skill picks a mode from the input (task text, plan path, --fast/--auto…) and loads references like intent-detection.md and blocking-gates.md as needed. Given a plan path, it reads plan.md and phase-*.md first.
PreToolUse
Before each tool call: privacy-block.cjs blocks Read/Write/Edit/Bash on .env, credentials, keys; the model must ask you, then retry with APPROVED:. scout-block.cjs blocks heavy dirs from .ckignore (node_modules, dist, .git…) but allows build commands. context-firewall.cjs sizes the call (file bytes, glob breadth, shell output) and answers allow → warn → narrow → block: warn at 256 KB / block at 2 MB for reads, 128 KB / 512 KB for shell output. descriptive-name.cjs reminds file-naming conventions before Write.
SubagentStart
When cook spawns tester or code-reviewer: subagent-init.cjs injects ~200 tokens of minimal context (cwd, plan, report path, rules). team-context-inject.cjs adds teammate info under Agent Teams. Subagents don't see the conversation, so the brief must be complete.
PostToolUse
After Write/Edit: dev-rules-reminder repeats rules; plan-format-kanban.cjs warns if plan.md uses file names as link text. After Agent/Task/TodoWrite: session-state.cjs saves progress for statusline and handoff. agent-behavior-linter.cjs quietly records tool behavior.
SubagentStop / Stop

Cook already tests and reviews. Add /ak:test or /ak:code-review only when you want an independent gate.

How the /ak:agentkit router thinks

  • Proportionality: a named skill goes straight to that skill; one obvious domain goes straight to its owner; plain chat needs no workflow.
  • Chain skeleton: understand → decide → execute → verify → deliver. Chains only move forward. A failure triggers a detour, then resumes at the failed link.
  • Collapse rule: drop a link if it takes under ~5 minutes, produces nothing later links reread, and skipping it removes no required verification.
  • Insertion rule: epic size adds planning; high risk adds verify + independent review + explicit approval before irreversible steps; 2+ domains split execution per domain.
  • Passing context: 1–2 links pass it in chat. Longer chains write files to plans/reports/ and pass paths, not summaries.
  • When to spawn subagents: only for a clean context, a tool boundary, parallelism, or a specialist prompt. Max 3–4 in parallel, with disjoint file ownership.

Vì cook đã có sẵn test và review, chuỗi cook → test → code-review → ship chỉ cần thêm /ak:test hay /ak:code-review khi bạn muốn một cổng kiểm tra độc lập.

Router /ak:agentkit nghĩ thế nào

  • Proportionality gate: đã gọi tên skill thì đi thẳng tới skill đó. Một domain rõ ràng thì đi thẳng tới owner của domain đó. Nếu chỉ là trò chuyện thì không cần workflow.
  • Khung chuỗi: understand → decide → execute → verify → deliver. Chuỗi chỉ chạy tiến. Gặp vấn đề thì rẽ nhánh (detour) rồi quay lại đúng mắt xích đã lỗi.
  • Collapse rule: gộp hoặc bỏ một mắt xích khi nó dưới khoảng 5 phút, không sinh artifact nào được đọc lại, và việc bỏ nó không làm mất bước verify mà mức rủi ro đòi hỏi.
  • Insertion rule: việc cỡ epic thì thêm bước decide (plan). Rủi ro cao thì thêm verify và một vòng review độc lập, cộng thêm xin phép trước bước không thể đảo ngược. Từ 2 domain trở lên thì chia execute theo domain.
  • Truyền context: chuỗi 1–2 mắt xích truyền trong hội thoại. Chuỗi dài hơn ghi artifact ra file (plans/reports/) và truyền đường dẫn thay vì tóm tắt.
  • Khi nào spawn subagent: chỉ khi được lợi một trong bốn thứ: context sạch, giới hạn tool, chạy song song, hoặc system prompt chuyên gia. Tối đa 3–4 agent song song, và các agent phải sở hữu file tách biệt.

Hooks

Hooks are Node scripts (.cjs) registered in ~/.claude/hooks/hooks.json, fired by runtime lifecycle events. Most are fail-open: if a hook crashes, the action continues and the error is logged. Each hook checks isHookEnabled('<name>'), so you can turn any one off in config.

Turn a hook off or on

# Disable simplify-gate for this project (committable)
ak config prefs set hooks.simplify-gate false --scope project
# Re-enable (no key = enabled)
ak config prefs unset hooks.simplify-gate --scope project
# Temporary env switch (simplify-gate only)
CK_SIMPLIFY_DISABLED=1 claude

Rules

Rules are Markdown files in ~/.claude/rules/, loaded every session. They set the default way of working for every skill. Skills are specific workflows; rules are house rules. Your own instructions and CLAUDE.md always win.

primary-workflow

Five steps: brainstorm the outcome (outcome, constraints, non-goals, acceptance), inspect, plan & implement, verify, review & finish. For bugs: prove the cause before choosing a fix.

development-rules

KISS, DRY. Deliver the full requested scope, nothing extra. YAGNI only with --yagni. No fake data or mocks to pass checks. Never hide failing tests. Conventional commits, no AI mentions.

orchestration-protocol

Every subagent brief includes task, files to read, files it may edit, acceptance, constraints, work context, report path, and scope flags (especially --yagni). Ends with DONE / DONE_WITH_CONCERNS / BLOCKED / NEEDS_CONTEXT. Stuck below fable? Ask kongming.

review-audit-self-decision

Don't reverse a verified decision over an abstract audit concern. Never silently undo a user decision. Establish the threat model before fixing security findings. No plan IDs or finding codes in comments or commits.

skill-workflow-routing

Template chains: Core [brainstorm]→[plan]→[implement]→[test]→[review]→[ship]→[journal], Bugfix [frame]→[scout]→[diagnose]→[choose fix]→[implement]→[test]→[review], and Investigation.

skill-domain-routing

Pick skills from the live installed catalog, not memory. One primary skill per intent. Never call a skill that isn't installed. New: optional "shadow comparison" via ak eval decision (domain-routing profile, max 15 capabilities), only on request; experimental evidence only.

documentation-management

Update docs only when behavior, setup, commands, architecture, or contracts change. Plans and reports are records, not evergreen docs. New: changing an operational route outside the repo (deploy path, log or credential source, webhook/OAuth/DNS, backup) counts as docs impact.

process-management

Track every background process (PID, port, worktree). Reuse or stop stale ones instead of grabbing a new port. Stop what you started. Never kill processes you don't own.

Full rule text lives in ~/.claude/rules/ on a machine with AgentKit installed. This site publishes summaries only.

Tips & common mistakes

Golden rules

  1. Size the chain to the risk, not habit. One-file edit: /ak:cook --fast or a domain skill. Auth, payments, public APIs: keep plan, validate, review, security.
  2. Cook already tests and reviews. Add /ak:test or /ak:code-review only for an independent gate before shipping something sensitive.
  3. Always read the plan before cooking. --advice and --auto don't replace this. Use plan.html (from --html).
  4. Pair --tdd: if plan used it, cook uses it too.
  5. Pass the plan path to cook (/ak:cook plans/…/plan.md) instead of re-describing. Cook reads state files first and won't re-ask settled questions.
  6. Don't re-plan without new facts. Fix the broken step and move on.
  7. Save --advice and --ultra for hard calls. On every command they just burn quota.
  8. /ak:ship opens a PR; it doesn't prove a merge or green CI. Use --merge for a reviewed merge that waits for CI.
  9. Open a new session after installing or updating a kit. Missing skills usually mean the runtime hasn't reloaded.
  10. Four skills are manual-only (disable-model-invocation): /ak:advise, /ak:ask, /ak:coding-level, /ak:loop. The model never picks them; type them yourself.
  11. Calling a skill that isn't installed is an error. Check with ak skills list or /ak:find-skills.

Save context & tokens

  • In long chains, pass artifacts as files (plans/reports/), not pasted text.
  • Use /ak:scout or Explore agents to scan a repo: raw output stays in the subagent, you get the conclusion.
  • Running out of context: /ak:handoff writes a continuation contract; open a new session. Add --dispatch --agent <id> to hand it to another runtime.
  • Long autonomous work: run /ak:goal-warmup "goal" first to lock an Outcome Contract and surface blockers, then /goal.
  • Find token hogs: ak usage limits --provider claude, ak insights skills, /ak:context-engineering.

Mẹo & lỗi thường gặp

Nguyên tắc vàng

  1. Chọn độ dài chuỗi theo rủi ro, không theo thói quen. Sửa một file thì dùng /ak:cook --fast hoặc skill domain. Auth, thanh toán hay public API thì giữ đủ plan, validate, review và security.
  2. Cook đã tự test và review. Chỉ thêm /ak:test hay /ak:code-review khi cần một cổng kiểm tra độc lập, chẳng hạn trước khi ship một thay đổi nhạy cảm.
  3. Luôn tự đọc plan trước khi cook. --advice hay --auto không thay được bước này. Dùng plan.html (tạo bằng --html) để đọc cho dễ.
  4. Dùng --tdd theo cặp: nếu plan có --tdd thì cook cũng phải có.
  5. Truyền đường dẫn plan cho cook (/ak:cook plans/…/plan.md) thay vì mô tả lại. Cook đọc state file trước và không hỏi lại những gì plan đã chốt.
  6. Đừng re-plan khi không có dữ kiện mới. Hãy sửa đúng bước hỏng rồi đi tiếp.
  7. Dành --advice và --ultra cho quyết định khó. Gắn vào mọi lệnh chỉ đốt quota.
  8. /ak:ship mở PR, không chứng minh là đã merge hay CI xanh. Muốn merge có review và chờ CI thì dùng --merge, hoặc theo dõi CI riêng.
  9. Sau khi cài hoặc cập nhật kit thì mở phiên mới. Skill không hiện là do runtime chưa nạp lại.
  10. Có 4 skill chỉ gọi được thủ công vì có disable-model-invocation: /ak:advise, /ak:ask, /ak:coding-level, /ak:loop. Model sẽ không tự chọn chúng, bạn phải gõ đích danh.
  11. Gọi skill không tồn tại là lỗi. Hãy kiểm tra bằng ak skills list hoặc /ak:find-skills.

Tiết kiệm context & token

  • Chuỗi dài thì truyền artifact qua file (plans/reports/) thay vì dán nội dung vào hội thoại.
  • Dùng /ak:scout hoặc agent Explore để quét repo, vì kết quả thô nằm trong context của subagent và phiên chính chỉ nhận kết luận.
  • Hết context giữa chừng: dùng /ak:handoff để tạo "continuation contract" rồi mở phiên mới. Nếu muốn giao cho runtime khác thì thêm --dispatch --agent <id>.
  • Việc dài và tự động: chạy /ak:goal-warmup "goal" trước để chốt Outcome Contract và phát hiện blocker, sau đó mới chạy /goal.
  • Tìm chỗ tốn token: ak usage limits --provider claude, ak insights skills, /ak:context-engineering.
